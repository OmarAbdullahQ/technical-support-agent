# Technical Support Knowledge Base

This document contains trusted support guidance for the `technical` intent.

## Scope

Use this document for requests classified as `technical`.

The guidance is intended for retrieval and extractive QA.

## Initial triage

1. Start troubleshooting by identifying the exact symptom.
2. Collect the complete error message when available.
3. Record when the issue started.
4. Ask whether the problem affects one user or many users.
5. Check recent changes before assuming a root cause.
6. Search logs for ERROR, FATAL, EXCEPTION, and WARN entries.
7. Preserve the original error text for escalation.
8. Check DNS when a hostname cannot be reached.
9. Check the destination port when a service is unreachable.
10. Connection refused often means the port is closed or unused.

## Logs and errors

11. A timeout can indicate filtering, routing, overload, or packet loss.
12. Check database connection pool usage under load.
13. Suspected production corruption should be escalated.
14. Check container logs when a service exits after startup.
15. Verify required environment variables are present.
16. Adapter-based models require the correct base model.
17. Offline mode prevents downloading missing model files.
18. Model quality issues are different from model loading issues.
19. Start troubleshooting by identifying the exact symptom.
20. Collect the complete error message when available.
