# Upgrade Support Knowledge Base

This document contains trusted support guidance for the `upgrade` intent.

## Scope

Use this document for requests classified as `upgrade`.

The guidance is intended for retrieval and extractive QA.

## Upgrade planning

1. Review release notes before upgrading.
2. Confirm the current version and target version.
3. Check supported upgrade paths.
4. Back up critical configuration before a major upgrade.
5. Test upgrades in a non-production environment when possible.
6. Document rollback steps before starting.
7. Check operating system and runtime compatibility.
8. Review deprecated features.
9. Preserve a copy of the original configuration.
10. Check new required environment variables.

## Compatibility

11. Back up the database before risky schema migrations.
12. Do not rerun a failed production migration blindly.
13. Verify migration completion before serving production traffic.
14. Run health checks after deployment.
15. Compare logs before and after the upgrade.
16. Re-run regression tests after changing ML dependencies.
17. Check CUDA and PyTorch compatibility for GPU environments.
18. Escalate if rollback is unsafe or data integrity is uncertain.
